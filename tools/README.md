# Studio XML Sync · v1.0.0

Локальный инструмент для работы Codex и разработчика с Save + Main Menu Pack.
Он переносит изменения из файлов Luau в обе поставляемые XML-модели, чтобы
демоместо и импортируемая модель не отставали от исходников.

## Установка и совместимость

Скачай исходники репозитория (Code → Download ZIP) и распакуй. Нужен Python
3.10 или новее; внешние библиотеки, ключи API и сетевой доступ не нужны.
Проверено на Windows с Python 3.12.14. Команды ниже запускаются из корня
репозитория; если команда `python` недоступна, укажи полный путь к Python.
Linux/macOS используют тот же стандартный Python, но отдельно здесь не проверены.

Поддерживаются именно текстовые Roblox XML v4 `.rbxmx`/`.rbxlx` этого пака.
Бинарные `.rbxm`/`.rbxl`, произвольные проекты и Rojo-проекты не поддерживаются.
Код распространяется на условиях CC0 из корневого LICENSE.txt; сторонние
библиотеки и материалы в это обновление не добавлены.

## Проверка без записи

```console
python tools/studio_sync.py check
python tools/studio_sync.py check --json
```

Команда сверяет пути, классы и Source всех 14 скриптов в обеих XML-моделях.
Неожиданный скрипт, потерянный скрипт, дубликат или неверный класс — ошибка,
а не повод автоматически менять структуру игры. Клиентские LocalScript
остаются в StarterPlayerScripts, серверные скрипты — в ServerScriptService.

Коды завершения: **0** — совпадение (или успешная сборка), **1** — исходники
отличаются от XML при `check`, **2** — ошибка входных данных или записи.
`--json` выводит JSON только при успешном разборе; ошибки идут в stderr.
Его можно применять в проверках перед коммитом без Studio.

## Пример: изменить заголовок меню

1. Измени значение TITLE в `Config.lua`, сохрани UTF-8.
2. Запусти `python tools/studio_sync.py check`: обе модели покажут Config.lua
   в списке изменений, код завершения будет 1.
3. Создай отдельную сборку:

```console
python tools/studio_sync.py build --output-dir builds/menu-title
```

В новой папке появятся `SaveMenuDemo.rbxlx`, `SaveMenuStarterPack.rbxmx` и
`sync-report.json`. Папка назначения должна быть новой. Существующие файлы и
входные шаблоны не перезаписываются. При ошибке проверки сборка не начинается.
Повтори с другим именем папки для следующей сборки.

4. Открой полученный `builds/menu-title/SaveMenuDemo.rbxlx` в Studio.
5. Нажми Play, проверь новый заголовок, настройки, чекпоинты и Output.
   Останови тест и повтори его с двумя игроками через тестовый сервер.
6. Для установки в другую тестовую игру импортируй полученный `.rbxmx` и
   перенеси папки по таблице в корневом README. Не добавляй второй комплект
   поверх демоместа. Не переноси серверный код в ReplicatedStorage.
7. После ручной проверки скопируй **оба** результата обратно в корень,
   запусти `check` снова и проверь разницу перед коммитом. Старый релизный ZIP
   сам не обновляется: это отдельная операция выпуска.

В отчёте находятся изменённые скрипты, количество скриптов, SHA-256 входных и
выходных XML и нормализованных исходников. Пути компьютера и секреты в отчёт
не включаются. Исходники нормализуются к LF без BOM; пробелы и конечные
переводы строк остаются значимыми. Для неизменённых XML байты сохраняются
полностью. При изменениях стандартный XML-сериализатор может изменить
оформление XML; имена, классы, referent, объекты карты и свойства сохраняются
семантически. XML-комментарии сохраняются, processing instructions — нет.

## Структура и источник истины

| Файл | Назначение |
|---|---|
| `tools/studio_sync.py` | CLI, проверка каталога, планирование и сборка |
| `tools/test_studio_sync.py` | Регрессионные тесты на копиях настоящего пака |
| `tools/VALIDATION.md` | Фактически выполненные проверки и ограничения |
| `catalogue.json` | Явные имена, пути установки и классы |
| Корневые `.lua` | Исходники для обычного GitHub checkout |
| `SaveMenuStarterPack.rbxmx` | Шаблон импортируемой модели |
| `SaveMenuDemo.rbxlx` | Шаблон демоместа с картой |

Развёрнутые папки установки из catalogue.json также поддерживаются вместо
плоского размещения. Если обе копии файла существуют и различаются, инструмент
отказывается выбирать за тебя. Сначала устрани расхождение. Для другого корня:

```console
python tools/studio_sync.py check --root path/to/unpacked-pack
python -m unittest discover -s tools -p "test_*.py" -v
```

## Работа через Codex и ограничения

Попроси Codex изменить конкретный файл Luau, показать разницу, выполнить
`check`, собрать в новую папку и запустить тесты. Затем открой результат
в Studio для проверки движком. Это конкретный файловый маршрут без локального
сервера, HTTP-моста, открытых портов и доступа к DataStore.

При разработке обнаружены доступный GitHub-коннектор и Python; запущенный
Roblox Studio и инструменты связи с Roblox/Blender не обнаружены. Наличие
локальной папки Roblox само по себе не доказывает связь со Studio.
**Инструмент не управляет открытым Studio, не синхронизирует его в реальном
времени и не публикует place в Roblox.** GitHub-публикация и импорт в Studio —
разные операции.

Это проверка упаковки, не компилятор Luau и не проверка безопасности игровой
логики. Синтаксис, репликацию, UI, входящие RemoteFunction-данные, реальные
сохранения и ограничения DataStore проверяй отдельно. Существующий
`verify_pack.py` требует Linux liblua5.4; на Windows эта зависимость отсутствует.
DTD/entities запрещены, размер каждого XML ограничен 32 MiB, пути исходников
не могут выходить из корня, в том числе через символьные ссылки. Инструмент
рассчитан на доверенную локальную копию; не запускай параллельную запись в
источники во время сборки. Изменения объектов карты делай в Studio и сохраняй
обновлённые шаблоны: этот CLI переносит только Source уже существующих скриптов.
